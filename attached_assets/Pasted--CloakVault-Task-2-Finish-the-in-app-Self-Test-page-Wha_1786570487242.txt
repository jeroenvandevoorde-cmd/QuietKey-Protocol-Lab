# CloakVault — Task #2: Finish the in-app Self-Test page

## What & why

All the real test suites already exist and pass in vitest: RFC 8452 KATs, capsule round-trip/tamper, the RS boundary suite, and the footer-codec 1000-round-trip / checksum / erasure tests. The in-app Self-Test page (`src/pages/self-test.tsx`) is currently only a shell. This task **assembles that page from the EXISTING tests** so a user can verify, in-browser, that their build is behaving correctly and that its output matches the frozen protocol test vector.

This is an assembly task, not a test-authoring task. The whole value of a self-test page is that it runs the *real* checks — so nothing may be weakened to make it fit or load faster.

## Non-negotiable rules

- **Assemble from the existing tests only.** No new test authoring, and do NOT alter the logic of any existing test.
- **Never reduce counts, sample subsets, or make any test probabilistic.** The 1000-round-trip test runs 1000, not a sample. The exhaustive checksum test stays exhaustive. If a suite is slow, see the smoke/full split below — do not shrink the suite.
- **No weakening, skipping, or `.only`/`.skip` shortcuts** to make the page pass or load.
- Do not touch `src/lib`, the crypto core, the codec, the spec, or the frozen test vector. Do not change any protocol constant.
- Standing rules hold: client-side only, no storage APIs, no runtime network requests, TEST USE ONLY banner present. The full validation set (97 vitest + 12 Python interop + cross-check) stays green.

## Behaviour

1. **Auto-run on load, grouped pass/fail.** On page load, automatically run a fast **smoke subset** and show pass/fail per group (KATs, capsule, RS, footer codec). Each group shows: name, pass/fail, count run, and time.
2. **"Run Full Suite" button.** Because the full suites (e.g. the 1000-round-trip and exhaustive checksum tests) may be too slow to auto-run on load, put the complete, unreduced suites behind an explicit **"Run Full Suite"** button. When pressed, it runs the *full* counts (1000 = 1000, exhaustive = exhaustive) in-browser and shows per-group results with real counts. The smoke subset is for the auto-run only; it must never replace or mask the full suite — the full suite is always available and always complete.
3. **Deterministic test-vector export.** A **"Export Test Vector"** button, gated behind an **explicit warning confirmation** (this is a developer/verification artifact; make the warning clear about what it is and that it is not something to share carelessly). On confirm, it exports the deterministic test-vector JSON, and its **output must byte-match `docs/cloakvault-v3-test-vector.json`** (same entropy → Vault Key → capsule → codeword → 142-char token → fingerprint). This proves the running build reproduces the frozen vector.

## Done looks like

- Self-Test page auto-runs a smoke subset on load and shows pass/fail per group; the full, unreduced suite is runnable in-browser via a button, with real counts displayed.
- The "Export Test Vector" button (behind a warning) produces output that matches `docs/cloakvault-v3-test-vector.json` exactly.
- **No test weakened, skipped, sampled, or made probabilistic** anywhere.
- The app's existing validation set stays green; nothing under `src/lib`, the spec, or the vector changed.

## Relevant files
- `src/pages/self-test.tsx` (the shell to build out)
- `src/lib/**/tests/*` (the existing tests to surface — reuse, do not alter)
- `docs/cloakvault-v3-test-vector.json` (the export must match this)

Report: what the smoke subset covers vs the full suite, confirmation that no test was reduced or altered, and confirmation the exported vector byte-matches the frozen one.
