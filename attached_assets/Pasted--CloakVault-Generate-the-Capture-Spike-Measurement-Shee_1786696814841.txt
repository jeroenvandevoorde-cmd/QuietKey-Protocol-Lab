# CloakVault — Generate the Capture-Spike Measurement Sheet (sheet only, not the spike)

## What this is

A small, contained generation task: produce the printable sheet and ground-truth file for the upcoming hardware capture spike (Task #3). This task is the SHEET ONLY — do not build any reader, OCR, classifier, or analysis harness. That comes later under its own prompt.

## Why it must come from the repo

The spike's endpoint is a real decode using the proven Python implementation, so every token on the sheet must be genuine output of the frozen v3 codec with known ground truth. The typography must be the product's own footer rendering (same font, size, and 48-char wrap), because reader performance is sensitive to glyph size/shape — a sheet at approximated typography measures the wrong thing.

## Build

A deterministic generator script, e.g. `artifacts/cloakvault/scripts/generate-spike-sheet.ts`, that **imports and reuses** the real codec and the real footer rendering (import from `src/lib` is required; modifying `src/lib` is forbidden), and emits:

1. `artifacts/cloakvault/spike/sheet.html` — a two-page A4 printable.
2. `artifacts/cloakvault/spike/tokens.json` — the ground truth.

### Page 1 — dense measurement sheet
- **Five token blocks**: `T0` (baseline control — will never be damaged) and `T1–T4` (damage targets). Each block: a small printed ID label (`T0`…`T4`) and the full 142-char token wrapped at the product's 48-char convention (3 lines), rendered with the product's exact footer typography.
- **Generous vertical whitespace between blocks (≥30 mm)** — damage application (a coffee ring is 4–6 cm across) must be able to hit one token without touching its neighbors. Damage isolation matters more than density; if five blocks don't fit with ≥30 mm gaps, drop to four (T0–T3).
- **A printed 50 mm scale bar** with tick marks, labeled "50 mm". This is the print-fidelity check: if a ruler says it isn't 50 mm on paper, the print was scaled and no captures from that batch are valid.
- A small printed sheet header: "CloakVault capture-spike sheet v1 · TEST TOKENS ONLY" plus a date line.

### Page 2 — realistic full-page variant
- One of the four curated real recipe bodies, laid out as the product renders a page, with **one token (`T5`)** in the real footer position (fake domain + `?id=` dressing as the product prints it). This page exists for the locate-the-footer-on-a-busy-page sanity test only.

### Non-printing screen note (like the previous damage-test sheet)
Include an on-screen-only box (hidden in print CSS) with the usage instructions:
- Print at 100% scale (no "fit to page"); verify with the 50 mm bar before any session.
- Print ~15–20 identical copies of page 1; page 2 needs only 2–3 copies.
- One damage condition per copy, applied across T1–T4 (four replicates per condition); **T0 is never touched** — if T0 fails to read cleanly in a session, the session (lighting/focus), not the damage, is at fault: discard and reshoot.
- Photo filenames: `{damage}-{severity}-{lighting}-{copyNN}.jpg` (token identity comes from the printed T-labels, not the filename).

### tokens.json (ground truth)
For each of `T0`–`T5`: `{ id, entropy_hex, vault_key_hex, capsule_hex, token, wrapped_lines[] }` — deterministic fixed TEST values (same spirit as the gate-packet generation), clearly marked TEST SECRETS ONLY. This file is what the future harness will score captures against and what the Python decoder will verify decodes with.

## Rules
- Deterministic: re-running the generator reproduces the identical sheet and tokens.json.
- Zero changes to `src/lib`, the spec, or the frozen vector; import-only. Full validation set (97 vitest + 12 interop + cross) stays green.
- No reader/harness/OCR work in this task.

Report: the six token strings' first/last 8 chars (for eyeball ID), confirmation the typography is imported from the product renderer (not re-styled), confirmation of determinism, and the file paths.
