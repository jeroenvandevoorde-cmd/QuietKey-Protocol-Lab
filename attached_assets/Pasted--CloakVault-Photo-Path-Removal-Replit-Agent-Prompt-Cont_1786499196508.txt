# CloakVault Photo Path Removal: Replit Agent Prompt

## Context (read this first)

You are modifying the existing CloakVault reference implementation in this Repl. Decision: document capture now happens outside the app (the platform's own text recognition pasted in, or typing it out), and camera capture returns later on dedicated hardware. The in-browser photo and OCR path is retired. This is a subtractive prompt: you are deleting a feature cleanly, not building anything. If you find yourself writing new UI or new capabilities, stop: you have misread the task.

## Scope and non-negotiable rules

- Delete only; no new features and no redesign of what remains. Explicitly do not add: save or load buttons, file import of text, beforeunload or unload handlers, any storage API use, any replacement OCR. These have been considered and declined.
- Do not modify: the crypto core, RS, the cloak grammar, the renderer, the decoder alignment logic (including junk-token tolerance and the edit-distance rules), the damage-model fuzz suite, or their tests. All remaining suites must stay green.
- Client-side only. No localStorage, sessionStorage, cookies, or IndexedDB anywhere (unchanged standing rule). Never log seeds or keys. The TEST USE ONLY banner stays on every page.

## Task 1: Remove the photo capture path from Recover

Delete completely: the file input and its instructional copy, the per-page cards and reorder controls, the crop step and corner-drag UI, the homography rectification, the grayscale and adaptive threshold utilities, the what-OCR-sees preview, the per-photo diagnostics line, and the tesseract worker module including parameter setup and whitelist derivation.

With photos gone, the textarea ownership state machine (linked and manual states, the rebuild and append notice) is meaningless: remove it. The textarea is simply an editable field that decode reads verbatim.

## Task 2: Remove the dependency

Remove tesseract.js from package.json and the lockfile, and remove any code that loads its worker or wasm assets. After this change the standing network rule tightens: the built app performs zero runtime network requests of any kind. There is no longer an OCR exception.

## Task 3: Update copy

The Recover page Document text copy becomes, near verbatim: "Recovery needs only this text plus your Vault Key. Get the text any way you like: paste it from your computer or phone's built-in text recognition (photograph the printed page, open the photo, select all the text, copy, paste here) or type it out by hand. Typos and gaps are tolerated: the decoder corrects what it can and reports exact counts. Prefer on-device text recognition; avoid uploading the document to cloud OCR services."

Keep the Create page full-quality print note as is.

## Task 4: Tests

Delete only tests that exclusively cover removed code (OCR parameter verification, crop, rectification, linked and manual textarea transitions). Keep everything else, in particular the decoder tolerance tests and the seeded damage-model fuzz suite: they are engine-agnostic and now cover pasted input.

## Acceptance criteria

1. The Recover page contains exactly: the Document text section, the Vault Key field, the Recover button, and the decode counts on every attempt, success or the red failure card. No file inputs or photo UI anywhere in the app.
2. tesseract.js is absent from dependencies and from the production bundle; no code imports it.
3. In the production build, the devtools network tab shows only the app's own static assets at load and zero requests afterward.
4. All remaining suites green, including crypto, RS, cloak engine, decoder tolerance, and the fuzz suite, with no diffs to their code.
5. A grep for storage APIs (localStorage, sessionStorage, indexedDB, document.cookie) still returns zero hits.
6. Paste-only recovery works end to end: paste text, enter Vault Key, Recover, counts shown.

## What not to do

No new buttons or handlers, no persistence, no replacement OCR, no grammar or renderer changes, no touching RS or crypto, no server. Delete cleanly and stop.
